## What to check at Level 0

| Line or block | Expect |
|---|---|
| Files | Three files, `acceptance-grbl 1 of 3 - T1.nc`, `2 of 3 - T2.nc`, `3 of 3 - T1.nc`, each loading its own tool: no `M6` |
| Start of each file | `G90 G94 G17`, `G20` (or `G21`), a `(Load T… and zero Z before starting)` comment, `M8`, `S18000 M3` |
| Line length | Every line within 79 characters (long comments shortened) |
| Dwell | `G4 P3.00` in file 2, in seconds |
| Not present | `G64`, `G90.1`, `G43 H`, `M7`, canned cycles |
| gSender file | One file with `T# M6` at each change; `post` warns that whether `M6` stops depends on the sender |
| End | `M5`, `M9`, `M30` |

## Steps

1. Run each file through Grbl's check mode (`$C`) first: no `error:` lines.
2. Common procedure Levels 1 and 3, running the three files in order: change the bit and re-zero Z between them.
3. If you use gSender (or CNCjs), set it to pause on `M6`, and run the `-gsender` file instead: it must stop at each change and let you jog and probe.

## Pass criteria

The common procedure's table, plus:

| Check | Target | Measured | ✓ |
|---|---|---|---|
| `$C` check mode on each file | No errors | | |
| Each file starts with the spindle on before cutting | Yes | | |
| gSender file pauses at each `M6` | Yes | | |

## Failure and what to report

The Grbl version (`$I`), the sender and its version, the exact `error:` or `ALARM:` number and line, and the measurements.
