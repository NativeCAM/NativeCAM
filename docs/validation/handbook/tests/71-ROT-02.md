title: Rotary check: G93 inverse time and turn speed
family: rotary
validates: That the controller runs inverse-time feeds (G93) as NativeCAM writes them, and how fast A really turns (the turn speed used for estimates and feed limits)
levels: 0, 1
risk: Low (no stock in the chuck; the tool raised)
time: 15 min
stock: None. Empty chuck
bits: None (the tool raised clear)
commands:
- nativecam-cli calibrate rotary -o calibration-rotary

## Steps

1. Make the program (for your own machine, add your project: `calibrate rotary my-machine.nativecam`). It writes the program, a recording sheet (`.html`) and a times file (`-times.csv`).
2. Remove the blank, raise Z well clear, and run it, timing each section from its first move to the next stop with a stopwatch.
3. Or do the same by hand in MDI: `G21 G90`, then `G93 G01 A360 F10` (should take **6.0 s**), then `G93 G01 X50 A90 F10` (also **6.0 s**), then `G94`, and check that a tool change (`M6`) still runs normally afterwards.
4. Write the measured times in the times file's `measured_s` column. Only times you measured.
5. Fit them (VH-CAL-03): `nativecam-cli calibrate fit calibration-rotary-times.csv my-machine.nativecam` reports the turn speed and the `G93` verdict.

## Pass criteria

| Check | Target | Tolerance | Measured | ✓ |
|---|---|---|---|---|
| `G93 G01 A360 F10` | 6.0 s | ±0.3 s | | |
| `G93 G01 X50 A90 F10` | 6.0 s | ±0.3 s | | |
| Rapid turn of 360° (note it) | — | — | | |
| Rapid turn of 720° back to A0 (note it) | — | — | | |
| `G94` restores normal feeds; `M6` works after it | Yes | — | | |
| Mach4 only: does a whole turn read the same with Rollover on or off? (note your setting) | — | — | | |

A turn of 10 s (or 0.1 s) means the controller ignored `G93` and fed in units per minute: don't run wrapped or 3D rotary jobs until it's fixed.

## Failure and what to report

The measured times, your controller's version and its A-axis settings (velocity, acceleration, rollover).
