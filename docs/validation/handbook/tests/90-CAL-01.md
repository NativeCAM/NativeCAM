## Setup

For your own machine, pass your project: `nativecam-cli calibrate timing my-machine.nativecam -o calibration-timing`, or use **File ▸ Calibration Programs…**. It writes the program, the recording sheet (`calibration-timing.html`) and the times file (`calibration-timing-times.csv`). The default window is 24 × 24 in (600 × 600 mm); `--window WxH` makes it smaller for a small machine.

Zero X and Y at the window's front-left corner and Z on the work. Keep every override (feed, rapid) at **100%**.

## Steps

1. Print the recording sheet. It lists every section with its estimate.
2. Run the program in the air. It stops before each section. Start the stopwatch on the section's first move and stop it at the next stop. Write each time on the sheet.
3. Note whether your controller shows the `(MSG,…)` text at each stop.
4. For the F-change line (two feeds alternating every 0.2 in, against one feed): listen and watch for stops or hesitations at each change.
5. Copy the times into the `measured_s` column of the times file. **Only times you measured.**
6. Fit them (VH-CAL-03).

## Pass criteria

| Check | Target | Measured | ✓ |
|---|---|---|---|
| Every section timed (count) | All | | |
| `(MSG,…)` text shown at each stop (note yes or no) | — | | |
| F-change line: hesitations at feed changes (note yes or no) | — | | |
| F-change verdict from the fit (note it) | — | | |
| Sections within 10% of the estimate before the fit (count) | — | | |

There's no pass or fail on the times themselves: they're measurements. The test fails only if the program can't run, or the machine leaves the window.

## Failure and what to report

The filled-in times file, the fit's output, your controller and its motion settings.
